# Демонстрационный сценарий

Около пяти минут. Нужны запущенный сервис (`./run.sh serve 6996` или образ из
Docker Hub) и три файла из архива организаторов «Для теста»: `CR000000_ПОП.dcm`,
`CR000000_ППОБ.dcm`, `CR000001_ЛПОБ.dcm`.

## 1. Сервис жив и автономен

```bash
curl localhost:6996/health
```

Все модели `true`, `status: ok`. Сеть наружу не нужна: образ работает и с
`docker run --network none`.

## 2. Пакетная обработка по контракту ТЗ

```bash
./run.sh batch "/путь/к/Для теста" ./out
```

В `./out/results.xlsx` — строка на снимок: область, вердикт, тип нарушения,
статус, время, `quality_prob` и пояснение. Ожидаемо: позвоночник — «Присутствуют
посторонние предметы», правое бедро — «Некорректная укладка», левое — годно.

## 3. Разбор одного снимка в браузере

Откройте `http://localhost:6996/` и перетащите три файла.

- **Позвоночник.** Центры тел позвонков, ось с углом 1,0° (в норме), верх
  крыльев таза в кадре; красным обведены тонкие яркие структуры вне колонны —
  вердикт «посторонние предметы». В списке проверок: величина, порог, сработало.
- **Правое бедро.** Контур кости, опорные точки и ось диафиза: наклон 7,9° —
  «Некорректная укладка». Под моделью — признаки, толкнувшие к решению.
- **Левое бедро.** Наклон 2,4°, годно.

## 4. Устойчивость

Подложите в каталог битый файл: строка уходит со статусом `Failure`, текст
ошибки — в `details`, остальные файлы обрабатываются.
