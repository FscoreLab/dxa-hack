# Руководство пользователя

Сервис отвечает на один вопрос: годится ли денситометрическое исследование для
клинической интерпретации, и если нет — что именно нарушено.

## Через браузер

Откройте корневую страницу сервиса. Перетащите один или несколько DICOM —
получите таблицу: область, вердикт, тип нарушения, оценка уверенности и
короткое пояснение на языке критериев методических рекомендаций. По каждому
снимку — картинка разбора и список проверок: величина, порог, сработало ли.

На позвоночнике картинка показывает то, чем решает сервис: центры тел
позвонков, ось с углом, коридор колонны, верх крыльев таза и красным — тонкие
яркие структуры вне колонны. Рамки вокруг них ставятся, только если правило
посторонних предметов сработало. На бедре — контур кости, опорные точки и ось
диафиза.

## Через API

```
curl -X POST localhost:6996/predict/file -F file=@CR000000.dcm
```

Каталог целиком:

```
curl -X POST localhost:6996/predict \
     -H 'Content-Type: application/json' -d '{"input":"/data/input"}'
```

Таблица по контракту ТЗ:

```
curl -X POST localhost:6996/predict/xlsx \
     -H 'Content-Type: application/json' -d '{"input":"/data/input"}' -o results.xlsx
```

Таблица и картинки разбора одним архивом (`results.xlsx` + `overlays/<study_uid>/<image_uid>.png`):

```
curl -X POST localhost:6996/predict/zip \
     -H 'Content-Type: application/json' -d '{"input":"/data/input"}' -o results.zip
```

⚠ Для путей с кириллицей берите POST. В строке запроса такой путь обязан быть
процентно-закодирован, иначе запрос не разбирается вовсе: у организаторов
каталоги названы «НД_для_обучения» и «Для теста», и `GET ?input=…` с ними
падает ещё до обработчика.

## Что в ответе

| поле | значение |
|---|---|
| `anatomical_region` | «Поясничный отдел позвоночника» либо «Проксимальный отдел бедра» |
| `quality_class` | 0 — годно, 1 — есть нарушение |
| `violation_type` | типы через `;`, пусто при их отсутствии |
| `quality_prob` | вероятность нарушения в диапазоне [0;1] |
| `processing_status` | `Success` либо `Failure`; причина ошибки — в `details` |
| `time_of_processing` | секунды на изображение |
| `details` | пояснение сверх контракта: измеренные величины и подсказки |

Списки типов закрыты и согласованы с организаторами. Позвоночник:
«Некорректная укладка», «Не выровнена ось позвоночника», «Присутствуют
посторонние предметы». Бедро: «Некорректная укладка», «Некорректная область
интереса».

## Как читать вердикт

Вердикт выносится на уровне «исследование × область», а не по каждому кадру:
дефект виден на одном снимке из трёх, и решение раздаётся всем изображениям
этой области.

⚠ `quality_prob` и `quality_class` считаются по-разному и могут разойтись по
краям шкалы: вердикт на позвоночнике — «сработал хотя бы один тип», а
вероятность собирается из долей порога трёх типов и модели годности, приведённых
к рангам относительно обучающей выборки. Годная область
с оценкой 0,7 — это не ошибка, а разные величины.

## Чего сервис не делает

- не ставит диагноз и не оценивает минеральную плотность;
- не проверяет уже нанесённые области измерения: в DICOM их нет, оценивается
  возможность корректной разметки, а не сама разметка;
- пометки «признаки сколиоза» — подсказка врачу, а не нарушение: сколиоз в этой
  разметке нарушением не считается.
