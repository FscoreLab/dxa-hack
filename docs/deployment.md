# Руководство по развёртыванию

Требование ТЗ, п. 3.2: решение запускается локально, без обращения к внешним
сервисам и без передачи изображений наружу. Все веса лежат в образе, сеть при
работе не нужна.

## Что нужно

| | минимально | рекомендуется |
|---|---|---|
| видеокарта | NVIDIA от 10 ГБ видеопамяти | NVIDIA от 16 ГБ видеопамяти |
| процессор | 4 ядра | 8 ядер |
| память | 8 ГБ | 16 ГБ |
| диск | 20 ГБ под образ | 30 ГБ |

Замер на RTX 3090: позвоночник около 3 с на снимок вместе с картинкой разбора,
бедро около 1 с; пик видеопамяти 7,7 ГБ (два экземпляра SAM 3: измеритель оси и
детектор центров тел с адаптером).

⚠ Без видеокарты сервис работает, но позвоночник считается около 185 с, бедро
около 55 с (замер на 12 ядрах, в образе OMP_NUM_THREADS=4): SAM 3 на процессоре —
основная часть времени. Лимит ТЗ — 180 с на исследование, поэтому видеокарта обязательна.

## Готовый образ

```
docker pull crazyfrogspb/dxa-celsus:1.7
docker run --rm --gpus all -p 6996:8000 -v /путь/к/данным:/data:ro crazyfrogspb/dxa-celsus:1.7
```

Все веса, включая SAM 3, уже внутри; сеть при работе не нужна.

Если Docker Hub недоступен, тот же образ архивом в Yandex Object Storage
(6,9 ГБ, ссылка действует до 15.10.2026 включительно):

```bash
curl -O https://storage.yandexcloud.net/dxa-hack-delivery-b751cef25ed7/dxa-celsus-1.7.tar.gz
curl -O https://storage.yandexcloud.net/dxa-hack-delivery-b751cef25ed7/dxa-celsus-1.7.tar.gz.sha256
sha256sum -c dxa-celsus-1.7.tar.gz.sha256
docker load -i dxa-celsus-1.7.tar.gz     # появится crazyfrogspb/dxa-celsus:1.7
```

## Сборка из исходников

```
git clone https://github.com/FscoreLab/dxa-hack && cd dxa-hack
./run.sh serve 6996
```

`run.sh` соберёт образ и поднимет API; каталог `./data` клона монтируется в
контейнер как `/data` — данные для `/predict` кладите туда. Отдельно:

```
docker build -t dxa-qc:latest .
docker run --rm -p 6996:8000 -v /путь/к/данным:/data:ro dxa-qc:latest
```

`run.sh` по умолчанию отдаёт контейнеру все видеокарты (`--gpus all`);
`DXA_GPU=none ./run.sh ...` — без видеокарты, `DXA_GPU=device=0` — конкретная.
У ручного `docker run` добавьте `--gpus all` сами.

⚠ Веса SAM 3 (3,3 ГБ) в git не входят: `.hfcache/sam3` нужно положить рядом до
сборки, иначе `docker build` упадёт на `COPY` (из готового образа или с Hugging Face с
зафиксированной ревизией — README, «Быстрый старт»). Адаптер детектора тел `models/kp_sam3_lora.pt` (7 МБ) лежит в
git. SAM 2.1 образу больше не нужен. Это сделано намеренно — образ обязан быть
автономным, а качать веса на запуске в контуре заказчика нельзя.

## Переменные окружения

| переменная | по умолчанию | зачем |
|---|---|---|
| `DXA_DATA_ROOT` | `/data` | каталог, внутри которого разрешено обрабатывать. ⚠ Без него `/predict` принимал бы любой путь на сервере и выдавал структуру файловой системы |
| `DXA_SAM3_PATH` | `/app/.hfcache/sam3` | веса SAM 3: ось, центры тел, эмбеддинг области |
| `DXA_SAM3_REQUIRED` | `1` в образе | при `1` отсутствие SAM 3 или адаптера детектора останавливает запуск, а не уводит на запасной метод |
| `HF_HUB_OFFLINE` | `1` | запрет сетевых обращений за весами |

## Проверка после развёртывания

```
curl localhost:6996/health
```

Все семь моделей должны быть `true`, `status` — `ok`. Если `ось позвоночника
SAM 3` или `центры тел позвонков (детектор)` равны `false` — веса не подложены,
и вердикты будут отличаться от тех, на которых измерено качество: без детектора
посторонние предметы и укладка позвоночника меряются заглушкой.

⚠ Отдельно проверьте `опорные распределения годности`. Без
`models/quality_refs.json` сервис не стартует: непрерывная оценка считалась бы
другой шкалой, чем та, по которой считается ROC-AUC.

## Разовый прогон без API

```
./run.sh batch /путь/к/dicom ./out          # ./out/results.xlsx и ./out/overlays.zip
```

Внутри контейнера то же самое:
`python scripts/pipeline/run_service.py --input /data/input --output /data/output/results.xlsx`
(картинки разбора — `overlays.zip` рядом с таблицей; `--no-overlays`, чтобы не собирать)
