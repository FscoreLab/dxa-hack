# Оценка качества денситометрических исследований

Сервис проверяет DXA-исследование на пригодность к клинической интерпретации:
определяет анатомическую область, выносит вердикт «годно / есть нарушение» и
называет тип нарушения. Задача НПКЦ ДиТ, хакатон «Лидеры цифровой
трансформации» 2026. Команда «Цельсоноиды».

## Что умеет и чего не умеет

**Умеет.** Поясничный отдел позвоночника и проксимальный отдел бедра. Область
и сторону определяет сам — тегов области в данных нет. Пять типов нарушений:

| область | тип | чем решается |
|---|---|---|
| позвоночник | Некорректная укладка (охват кадра: Th12 сверху, гребни снизу) | обученная модель |
| позвоночник | Не выровнена ось позвоночника | измерение с порогом |
| позвоночник | Присутствуют посторонние предметы | измерение с порогом |
| бедро | Некорректная укладка | обученная модель |
| бедро | Некорректная область интереса | обученная модель |

Каждый вердикт объясняется: величина и порог для правил, вклад признаков для
моделей, картинка разбора поверх снимка. Ошибка на одном файле не роняет
обработку каталога.

**Не умеет.** Ротацию бедра отдельным типом не выдаёт: в обучающей разметке
нет ни одного примера. Проекцию не определяет: в данных только прямая, других
проекций не было. Не выдаёт текстовое описание в DICOM SR и не исправляет
разметку автоматически (дополнительные пункты ТЗ, п. 2.6). Не ставит диагноз
и не оценивает минеральную плотность.

**Ограничения.** Данные одного аппарата (GE Lunar Prodigy Advance), 100
исследований; на другом аппарате качество нужно перемерять. Типы с шестью–
десятью примерами нарушения — предварительные: доверительный интервал там шире
любой разницы между подходами.

## Качество

Кросс-валидация на 249 размеченных областях (72 нарушения), пять фолдов по
исследованиям; всё, что подбирается по меткам, — только на обучающей части
фолда. Снимок на 25.09.2026:

| задача | n | нарушений | ROC-AUC (95 % ДИ) | F1 (95 % ДИ) | чувств. | специф. | сбал. точн. |
|---|---|---|---|---|---|---|---|
| **годность, все области** | 249 | 72 | **0,888** (0,84–0,93) | **0,731** (0,64–0,81) | 0,736 | 0,887 | 0,812 |
| годность · позвоночник | 99 | 31 | 0,895 (0,83–0,95) | 0,762 (0,63–0,87) | 0,774 | 0,882 | 0,828 |
| годность · бедро | 150 | 41 | 0,885 (0,80–0,95) | 0,707 (0,56–0,82) | 0,707 | 0,890 | 0,799 |
| посторонние предметы | 99 | 17 | 0,972 (0,94–1,00) | 0,857 (0,70–0,97) | 0,882 | 0,963 | 0,923 |
| укладка бедра | 150 | 36 | 0,875 (0,78–0,95) | 0,693 (0,53–0,81) | 0,722 | 0,886 | 0,804 |
| ось позвоночника\* | 99 | 10 | 0,857 (0,75–0,94) | 0,421 (0,11–0,67) | 0,400 | 0,944 | 0,672 |

Интервалы — бутстрэп по исследованиям. F1, чувствительность и специфичность
считаются по бинарному решению сервиса, ROC-AUC — по `quality_prob`.
Сегментация бедра: IoU 0,890 (153 кадра). Успешно обработано 100 % файлов.

## Быстрый старт

Нужны Docker и видеокарта NVIDIA с 10 ГБ видеопамяти (без неё работает, но
около минуты на снимок позвоночника).

**Готовый образ** (все веса внутри, сеть при работе не нужна):

```bash
docker pull crazyfrogspb/dxa-celsus:1.0
docker run --rm --gpus all -p 6996:8000 -v /путь/к/dicom:/data/input:ro crazyfrogspb/dxa-celsus:1.0
curl localhost:6996/health
# разовый прогон каталога в таблицу:
docker run --rm --gpus all -v /путь/к/dicom:/data/input:ro -v $PWD/out:/data/output \
    crazyfrogspb/dxa-celsus:1.0 python scripts/pipeline/run_service.py \
    --input /data/input --output /data/output/results.xlsx
# рядом с таблицей — out/overlays.zip: картинка разбора на каждое изображение
```

**Сборка из исходников.** Веса SAM 3 (около 3,3 ГБ) в репозиторий не входят —
положите их в `.hfcache/sam3` до сборки. Проще всего взять их из готового образа
(токен не нужен, версия заведомо та, на которой проверено качество):

```bash
docker create --name sam3src crazyfrogspb/dxa-celsus:1.0
docker cp sam3src:/app/.hfcache/sam3 .hfcache/sam3 && docker rm sam3src
```

Либо с Hugging Face — модель закрытая, нужен одобренный доступ и `hf auth login`;
ревизия зафиксирована, иначе скачается другая версия весов:

```bash
hf download facebook/sam3 --revision 3c879f39826c281e95690f02c7821c4de09afae7 --local-dir .hfcache/sam3
```

Остальные веса — в `models/`. Сборка и запуск API:

```bash
./run.sh serve 6996
curl localhost:6996/health          # все модели true, status ok
```

Разовый прогон каталога в таблицу по контракту ТЗ:

```bash
./run.sh batch /путь/к/dicom ./out  # ./out/results.xlsx и ./out/overlays.zip
./run.sh batch архив.zip ./out      # zip-архив тоже принимается
DXA_FORMAT=csv ./run.sh batch /путь/к/dicom ./out   # results.csv вместо xlsx
```

Веб-интерфейс — корневая страница сервиса: перетащите DICOM, получите вердикт,
картинку разбора и список проверок. Подробнее — `docs/deployment.md`
(развёртывание) и `docs/user-guide.md` (API и чтение ответа).

## API

Сервис поднимается на порту 8000 контейнера. Пути к данным — внутри `/data`
(смонтируйте каталог с DICOM туда; для путей с кириллицей используйте POST).

| ручка | что делает |
|---|---|
| `GET /health` | состояние моделей; `status: ok`, когда загружено всё |
| `POST /predict` `{"input": "/data/input"}` | обработать каталог, ответ — строки JSON |
| `POST /predict/xlsx` `{"input": "/data/input"}` | то же, таблицей `results.xlsx` по контракту ТЗ |
| `POST /predict/file` (multipart `file`) | один DICOM |
| `POST /explain/file` (multipart `file`) | один DICOM с картинкой разбора и списком проверок |
| `POST /predict/zip` `{"input": "/data/input"}` | каталог: архив с `results.xlsx` и `overlays/` — картинкой разбора на каждое изображение |
| `GET /` | веб-страница: загрузка DICOM и разбор решения |

Примеры (сервис запущен с `-v /путь/к/dicom:/data/input:ro -p 6996:8000`):

```bash
curl localhost:6996/health
# каталог или zip внутри /data — таблица по контракту ТЗ
curl -X POST localhost:6996/predict/xlsx -H 'Content-Type: application/json' \
     -d '{"input": "/data/input"}' -o results.xlsx
# то же плюс картинки разбора одним архивом
curl -X POST localhost:6996/predict/zip -H 'Content-Type: application/json' \
     -d '{"input": "/data/input"}' -o results.zip
# один файл: строка отчёта JSON, с quality_prob
curl -F file=@снимок.dcm localhost:6996/predict/file
```

## Формат входа и выхода

**Вход** — каталог с DICOM (поиск рекурсивный), zip-архив или один файл;
zip-архивы внутри каталога тоже распаковываются. Область и сторона
определяются по изображению, теги области не нужны. Размера пикселя в
выгрузке нет (PixelSpacing пуст) — берётся паспорт аппарата 0,6 × 1,05 мм;
углы и пороги считаются в пикселях и подобраны по разметке.

**Выход** — строка на изображение; первые восемь колонок — контракт ТЗ:

| колонка | значение |
|---|---|
| `path_to_study` | каталог исследования |
| `study_uid`, `image_uid` | StudyInstanceUID и SOPInstanceUID |
| `anatomical_region` | «Поясничный отдел позвоночника» / «Проксимальный отдел бедра» |
| `quality_class` | 0 — годно, 1 — есть нарушение |
| `violation_type` | типы нарушений через `;`, пусто, если их нет |
| `processing_status` | `Success` либо `Failure` |
| `time_of_processing` | секунды на изображение |
| `quality_prob` | вероятность нарушения в [0; 1] — по ней считается ROC-AUC |
| `details` | пояснение: измеренные величины и подсказки; у `Failure` — причина ошибки |

Вердикт выносится на область исследования и раздаётся всем её кадрам.
Рядом с таблицей пакетный прогон кладёт `overlays.zip` — дополнительные серии
(ТЗ, п. 2.6–2.7): `<study_uid>/<image_uid>.png`, та же картинка разбора, что в
веб-интерфейсе. Подробнее — `docs/user-guide.md`.

## Как устроено

Один DICOM на входе, одна строка отчёта на выходе.

1. **Чтение DICOM** (`dxa_io/dicom.py`). Полярность — по тегу и по гистограмме,
   нормировка по перцентилям 0,5–99,5.
2. **Область съёмки.** Логистическая регрессия на эмбеддинге энкодера SAM 3,
   снятом по маске кости; при уверенности ниже 0,6 — `Failure`, а не догадка.
3. **Маска кости.** Бедро — ансамбль пяти U-Net, обученных на псевдометках
   SAM 2.1. Позвоночник — трёхуровневый Otsu.
4. **Анатомия позвоночника.** Центры тел позвонков находит SAM 3 с дообученным
   адаптером LoRA и отбором цепочкой (`dxa_seg/kpdet.py`; учился на внешних
   наборах). По цепочке строится коридор колонны, ищется верх крыльев таза и
   тонкие яркие структуры вне колонны. Уровни L1–L4 — отдельная сеть.
5. **Признаки** (`dxa_feat/`, реестр наборов). Физические величины из
   методических рекомендаций: угол оси, запасы кадра, видимость крыла таза,
   площадь посторонних структур, форма и наклон бедра, разность сторон.
   До решения доходят 23.
6. **Вердикт** (`dxa_service/model.py`). Где нарушение сводится к одной
   величине с нормой (угол оси, площадь посторонних структур) — порог по ней;
   где условий несколько (укладка позвоночника, оба типа бедра) — среднее градиентного
   бустинга глубины 2 и логистической регрессии на своём наборе измерений. Годность позвоночника — «сработал хотя бы один тип», бедра —
   своя модель. Непрерывная оценка (`quality_prob`) — максимум трёх типов в
   долях порога своего правила, приведённый к рангу вместе с моделью годности
   (`dxa_service/quality.py`, опорные распределения — `models/quality_refs.json`).

## Структура

```
dxa_io/       чтение DICOM
dxa_seg/      маски кости, центры тел позвонков, уровни
dxa_feat/     признаки (реестр f_*.py) и названия для отчётов
dxa_eval/     модели голов (формат весов в models/heads.pkl)
dxa_service/  инференс: конвейер, модель, API, картинка разбора, веб-страница
models/       веса и пороги
scripts/pipeline/run_service.py   пакетный прогон каталога
docs/         развёртывание и руководство пользователя
```

## Известные ситуации

| ситуация | поведение |
|---|---|
| область не определена | строка с `Failure`, вердикт не выдаётся |
| файл не читается | `Failure`, текст ошибки в `details`, остальные файлы обрабатываются |
| нет весов SAM 3 или адаптера | в образе запуск прерывается (`DXA_SAM3_REQUIRED=1`) |
| детектор не нашёл тел позвонков | признаки по цепочке — «крыло видно, предметов нет», вердикт по остальным |
